# 설치와 사용

대상: 두 Mac 모두 macOS 14 이상. 빌드하는 Mac에는 Go 1.24 이상과 Xcode Command Line Tools가 필요합니다. 앱은 현재 Mac CPU용으로 빌드하며 원격 헬퍼는 arm64·amd64 둘 다 포함합니다. 외부 Go/Swift 패키지는 없습니다. Xcode 26 이상이면 Icon Composer 원본을 native Liquid Glass 아이콘으로 컴파일합니다. 이전 도구에서는 포함된 icns로 같은 디자인을 사용합니다. 앱 실행 최소 버전은 14를 유지합니다.

## 로컬 Mac에 앱 설치

```sh
make app
sh scripts/install-local.sh
```

`~/Applications/Worklink.app`을 Finder에서 엽니다. `/Applications`로 옮겨도 같은 사용자 설정과 전송 기록을 사용합니다. 업데이트 파일은 현재 앱 위치에 적용합니다. 메뉴바 아이콘이 나타나며 업무 모드는 OFF로 시작합니다. 기존 설치가 있으면 덮어쓰지 않습니다. 업데이트할 때는 앱을 종료하고 기존 앱을 다른 곳으로 옮긴 뒤 새 앱을 설치합니다.

시작 시 로그인 항목 등록을 요청합니다. macOS가 승인을 요구하면 시스템 설정의 로그인 항목에서 허용합니다. 앱 설정에서 자동 시작을 끌 수 있으며 다음 실행에도 그 선택을 유지합니다. 이 작업은 사용자 실행 시 수행하는 기능이며 개발 검증에서는 실제 로그인 항목을 변경하지 않았습니다.

## 기존 SSH 대상 등록

터미널에서 사용하는 기존 SSH 별칭을 입력합니다. 예: `office-mac`. 먼저 일반 SSH 접속이 성공하고 호스트 키 확인이 끝나 있어야 합니다. 앱은 비밀번호 입력창을 자동으로 처리하지 않습니다.

메뉴바 좌클릭 → 설정 → SSH 대상 추가. 원격 헬퍼 경로는 기본 `~/.local/bin/worklink`입니다. 대상 선택 후 **선택한 대상에 헬퍼 설치**를 누르면 해당 Mac의 CPU에 맞는 바이너리를 전송하고 사용자용 일일 정리 작업을 등록합니다. 사용자 SSH 설정은 수정하지 않습니다. GUI 로그인이 없어 정리 작업 등록이 실패하면 원인을 표시합니다. 헬퍼는 다음 연결 시 누락된 정리를 보완합니다.

일일 작업은 원격 Mac의 사용자 세션에서 기본 04:00에 짧게 실행 후 종료합니다. 로그아웃·전원 꺼짐으로 누락되면 다음 연결에서 보완합니다.

## 개발 서버 등록과 열기

메뉴바 좌클릭 → **개발 서버** 입력칸에 `5173` 또는 `localhost:5173/preview`를 넣고 **등록** 또는 Enter를 누릅니다. SSH 대상은 현재 이미지 전송 대상을 기본으로 선택하며, 여러 대상이 있으면 옆에서 바꿀 수 있습니다. 업무 OFF에서도 등록할 수 있습니다. 성공하면 입력을 비우며 오류는 입력 아래 표시하고 내용을 유지합니다. 로컬 포트는 기본으로 원격 포트와 같습니다. 다른 로컬 포트·이름·수정은 설정에서 지정합니다.

설정에서도 SSH 대상을 고르고 `5173`, `localhost:5173`, `Local: http://localhost:5173/preview` 등을 붙여넣습니다. 해석한 주소를 확인하고 표시 이름을 입력해 등록합니다. 로컬 포트는 기본으로 원격 포트와 같습니다. 충돌하면 다른 포트를 지정합니다. `/preview`·query·fragment는 유지합니다. 여러 URL이 있으면 후보 하나를 선택합니다.

팝업 맨 위 **업무 ON/OFF 스위치** 또는 메뉴바의 짧은 우클릭으로 업무 모드를 전환합니다. 메뉴바 아이콘을 **우클릭으로 0.5초 계속 누르면**, 버튼을 떼기 전에 **캡처 원본 유지 ↔ 원격 경로 자동 복사**가 한 번 전환됩니다. 긴 누르기로 모드를 바꾸면 현재 SSH 대상의 최신 캡처도 바로 준비합니다. **원본 유지로 전환하면 원본 이미지**, **자동 경로 복사로 전환하면 원격 경로**를 클립보드에 넣습니다. 가져오는 동안 다른 내용을 복사하면 덮어쓰지 않습니다. 새 캡처가 아직 감지·전송 중이거나 실패했다면 이전 사진을 대신 복사하지 않습니다. 팝업의 체크는 설정만 바꿉니다. 긴 누르기 뒤 버튼을 떼도 업무 상태는 바뀌지 않습니다. 트랙패드에서는 두 손가락으로 물리적으로 눌러 유지해 주세요. 가볍게 탭하면 짧은 우클릭으로 처리합니다. 아이콘 밖으로 드래그하면 누르기가 취소됩니다. 제목과 같은 줄의 **캡처 원본 유지**는 클립보드 완료 동작만 바꿉니다. 좌클릭하면 이름·짧은 localhost 주소·상태를 한 줄로 확인할 수 있고 **연결 가능**인 서버 항목을 클릭하면 기본 브라우저로 엽니다. 행 오른쪽 화살표를 펼치면 URL 옆 같은 줄의 문서 겹침 아이콘으로 주소를 복사하거나 **제목 확인**을 사용할 수 있습니다. 긴 URL은 말줄임으로 표시하며 툴팁에 전체 주소를 유지합니다. 원격 대상과 오류는 아래 표시합니다. 서버 목록은 표시된 로컬 포트 번호 오름차순이며 같은 포트는 기존 등록 순서를 유지합니다. 화살표를 제외한 행 전체가 같은 서버 열기 버튼입니다. 연결 가능한 행과 활성 버튼에 마우스를 올리면 배경 강조와 손 모양 커서를 표시합니다. 대기·업무 OFF·충돌 상태에서는 서버 열기를 비활성화하고 툴팁에 이유를 표시하며 상세 화살표는 사용할 수 있습니다. 개발 서버 제목 옆 **관리…**에서 상세 설정을 엽니다. ON/OFF 모두 같은 크기의 체인을 사용하며 OFF는 끊어진 체인과 약한 dimming으로 표시합니다. 일시 정지·오류는 같은 체인에 작은 표시를 붙입니다. 계속 클릭할 수 있습니다.

등록한 원격 포트는 입력한 loopback 주소를 먼저 확인하고, 연결이 안 되면 IPv4 `127.0.0.1`과 IPv6 `[::1]` 중 다른 주소를 확인합니다. 실제 연결된 주소로 터널을 구성하며 상세에 표시합니다. 양쪽에 다른 앱이 열렸으면 입력한 주소를 우선합니다. 기존 등록도 재등록 없이 이 동작을 사용합니다. `127.0.0.2` 등 다른 loopback IP는 지정 주소만 사용합니다.

미등록 포트는 탐색하지 않습니다. 등록한 주소·포트가 다른 앱에 의해 재사용되면 구분할 수 없으므로 해당 항목을 중지하거나 수정합니다.

## 이미지 전달

업무 ON 후 클립보드로 캡처합니다. macOS 캡처 단축키에 Control을 추가하면 클립보드로 저장할 수 있습니다. [Apple 캡처 안내](https://support.apple.com/en-us/102646)

이미지 종류를 확인한 뒤 클립보드에 제공된 원본 PNG·JPEG·TIFF·HEIF·WebP 표현을 재인코딩 없이 전송합니다. 기본은 전송 완료 후 현재 클립보드가 해당 캡처일 때만 원격 파일 경로로 바꿉니다. 에이전트 세션에 붙여넣습니다. 전송 완료 전에 붙여넣지 않도록 메뉴바 상태를 확인합니다. 배너·알림음은 없습니다.

메뉴바 체인 오른쪽 아래의 **작은 테두리·산 모양 사진 배지**는 캡처 원본 유지 ON을 뜻합니다. OFF에서는 체인만 보이며 아이콘과 메뉴바 영역의 크기는 그대로입니다. 원본 유지 ON에서 오류·일시 정지 표시는 배지와 겹치지 않게 왼쪽 위에 표시합니다. 업무 OFF에도 설정 표시는 흐리게 유지됩니다. 툴팁으로 업무 상태와 원본 유지/원격 경로 자동 복사 모드를 함께 확인할 수 있습니다.

메뉴 상단 **캡처 원본 유지**를 켜면 자동 전송은 유지하고 로컬 클립보드 이미지는 그대로 둡니다. 필요할 때 최근 이미지의 **경로 복사**를 눌러 에이전트 세션에 붙여넣습니다. 끄면 다시 완료 시 경로를 자동 복사합니다. 선택은 다음 실행에도 유지하고, 진행 중 전송은 완료 시점의 선택을 따릅니다. 전환 자체는 클립보드나 연결 상태를 바꾸지 않습니다.

두 모드 모두 최근 이미지의 **원본 복사**로 원격 원본을 같은 형식/byte로 클립보드에 넣을 수 있습니다. 업무 ON 및 원래 대상 연결이 필요합니다. 클릭할 때만 전용 SSH 연결의 별도 임시 채널에서 원본을 다운로드해 hash 확인 후 복사하고 다운로드 임시 파일을 제거합니다. 상주 캐시는 없으며 복사한 원본을 자동 재업로드하지 않습니다. 앱이 비정상 종료되어 남은 다운로드 파일은 다음 시작에 회수합니다. 새 내용을 복사하거나 업무 상태가 바뀌면 대기 중 복사는 취소합니다.

다른 내용을 복사했다면 전송만 완료하고 클립보드는 보존합니다. 최근 이미지를 개발 서버 위에 시간·대상·용량·상태의 한 줄로 표시합니다. 기본으로 최신 3개를 보여주고, 더 있으면 제목 옆 **전체 N개 보기**로 최대 5개를 펼칩니다. **접기**로 3개로 돌아오며 메뉴를 다시 열어도 기본 3개로 시작합니다. 문서 겹침 아이콘은 **경로 복사**, 사진 아이콘은 **원본 복사**, 실패 작업의 회전 화살표는 **재시도**입니다. 전체 형식·정보·오류는 행과 상태의 툴팁으로 확인합니다. 비활성 버튼에 마우스를 올리면 업무 OFF·만료·전송/원본 가져오는 중·원래 대상 연결 대기 등의 이유를 툴팁으로 확인합니다. 이미 정리된 원격 파일은 만료로 표시합니다.

처음 클립보드 접근 시 OS가 허용을 요구할 수 있습니다. 거부한 경우 상태에 원인을 표시하고 자동 읽기를 중지합니다. 시스템 설정에서 허용한 뒤 업무 OFF/ON으로 다시 시작합니다. 잠금·절전 중에는 감시와 연결을 중지하고, 복귀 시 이전에 켜둔 업무 모드만 복원합니다.

CLI의 원본 저장과 이미지 해석은 별도입니다. Codex 공식 문서가 명시한 공통 입력 형식은 PNG·JPEG입니다. Worklink는 다른 형식도 원본으로 전송하며, 에이전트의 해당 형식 지원 여부를 보장하지 않습니다. 자동 형식 변환은 하지 않습니다. [OpenAI 공식 이미지 입력 안내](https://learn.chatgpt.com/docs/image-inputs?surface=cli)

## 자원 한도와 정리

기본 후보였던 16/64 MiB는 4K 원본 RGBA가 약 32 MiB가 될 수 있음을 고려해 조정했습니다. 현재 기본은 원본 1개 **64 MiB**, 로컬 대기 **8개·256 MiB**, 원격 보관 **2 GiB**입니다. 앱 설정에서 용량을 조정할 수 있습니다. 초과 시 원본을 줄이지 않고 오류를 표시합니다.

원격 ACK와 완료 기록 저장 후 로컬 대기 복사본을 삭제합니다. 앱 재시작에서는 남은 작업을 자동 전송하지 않고 일시 중지 상태로 둡니다. 실패·대기 작업은 최근 목록에서 재시도하거나 업무 OFF 상태의 대기 파일 정리로 제거할 수 있습니다. 30분 지난 작업은 자동 재시도하지 않습니다.

원격은 하루 한 번 24시간 지난 관리 파일만 정리합니다. 실제 보관은 정상 일정에서 대략 24–48시간입니다. 오래 사용할 파일은 원격 CLI로 보관 표시하거나 프로젝트에 내보냅니다.

```sh
~/.local/bin/worklink image list
~/.local/bin/worklink image pin <ID>
~/.local/bin/worklink image export <ID> ./reference.png
~/.local/bin/worklink image cleanup --dry-run
~/.local/bin/worklink cleanup uninstall
```

## 개발·검증

```sh
make test
make previews
make icon-previews
python3 scripts/verify-app-icon.py
WORKLINK_DEV=1 .build/Worklink.app/Contents/MacOS/Worklink --dev
WORKLINK_TEST_SSH_HOST=office-mac python3 scripts/ssh-integration.py
WORKLINK_TEST_SSH_HOST=office-mac WORKLINK_QA_NATIVE=1 python3 scripts/ssh-integration.py
```

개발 모드는 별도 `~/.local/share/worklink-dev`를 쓰며 로그인 항목을 변경하지 않습니다. `WORKLINK_DATA_DIR`로 테스트 공간을 지정할 수도 있습니다. 실제 SSH QA는 원격·로컬의 별도 임시 폴더와 일시적 서버만 사용하고 끝나면 정리합니다. native QA는 사용자의 일반 클립보드 대신 이름이 고유한 테스트 클립보드를 사용합니다.

검증 결과와 미검증 범위는 [검증 기록](validation.md)을 확인해 주세요.


## 연결 대기와 포트 충돌

연결이 없는 동안 대기 이미지는 원본을 유지하고 같은 상태를 반복 저장하지 않습니다. 30분이 지난 대기 작업은 만료 상태를 한 번 저장하며 파일은 자동 삭제하지 않습니다. 다른 SSH 대상이 연결돼 있으면 그 대상의 대기 전송은 진행합니다.

로컬 포트 충돌은 해당 포트만 10→20→40→60초 간격으로 재시도합니다. 정상 포트 감시는 그대로 유지되며 원격 loopback 대상이 바뀌거나 연결을 새로 만들면 즉시 다시 시도합니다. 충돌을 해소해도 표시가 복구되기까지 최대 약 60초에 관리 주기·작업 시간이 더해질 수 있습니다. 설정 변경 또는 업무 OFF/ON은 현재 네트워크가 안정화된 뒤 새 연결을 시도합니다.

UI에는 내용이 바뀐 상태만 전달합니다. 명령 응답과 이미지 전송 완료는 이 제한을 받지 않습니다. 네트워크 단절을 이유로 업무 모드를 자동으로 끄거나 클립보드 감시 주기를 변경하지는 않습니다.

## 이동 중 네트워크와 저전력 모드

macOS 네트워크 경로가 미확인 또는 끊긴 동안에는 새 SSH 연결·주기 확인을 멈추고 진행 중인 Worklink 네트워크 작업을 취소합니다. 업무 ON 의도와 이미지 대기 원본은 유지합니다. 대기 사유는 팝업과 아이콘 툴팁에서 확인할 수 있으며 대기만으로 메뉴바 아이콘을 일시정지로 바꾸지는 않습니다. 경로가 3초 연속 유지되면 재개하되 기존 SSH 실패 backoff는 유지하고, 단절 직전 연결을 시작했다면 그 시점부터 최소 30초 뒤에 다시 연결합니다. 경로가 있어도 Tailscale·원격 SSH가 안 되면 기존 실패 재시도 간격을 따릅니다.

잠금·시스템 절전·업무 OFF에서는 네트워크 경로 감지와 예약된 복구를 중지합니다. 사용자 마우스·키보드 조작은 감시하지 않습니다. macOS 저전력 모드를 켜면 등록 포트 확인은 일반 5초에서 30초로 줄어들고, 등록 포트가 없는 대상은 60초마다 확인해 원격 헬퍼 연결을 유지합니다. 저전력 상태 변화만으로 SSH·진행 중 파일 전송·업무 세대를 재시작하지 않습니다.

개발 서버 제목 옆 새로고침으로 즉시 상태 확인을 요청할 수 있습니다. 2초 안의 반복 요청은 합치며 OFF·무경로·재연결 대기 시간을 우회하지 않습니다. 포트 자동 정리·상한 교체는 새 확인 결과의 기존 15초 기준을 유지하므로 저전력 모드에서 관측이 오래됐다면 새로고침 후 등록을 다시 시도해 주세요.

중단된 이미지는 복구 후 같은 ID로 원격 존재·ACK를 확인하고 이어갑니다. 네트워크가 없는 동안 만료 확인 타이머도 돌리지 않으며 복구 시 30분 경과 작업을 만료 처리합니다. 명시적으로 보낸 일반 파일은 자동 재전송하지 않으므로 연결 후 다시 보내 주세요. 이 정책은 반복 작업을 줄이기 위한 것이며 실제 배터리 절감률을 뜻하지 않습니다.

## 일반 파일 보내기

업무 ON 상태에서 선택한 이미지 전송 SSH 대상에 연결된 뒤 다음 중 하나를 사용합니다.

- Finder에서 파일을 Worklink 메뉴바 아이콘에 드롭합니다.
- Finder에서 파일을 선택하고 **서비스 → Worklink로 보내기**를 사용합니다.
- Worklink 팝업의 **최근 파일 → 파일 보내기…**에서 선택합니다.

일반 파일을 한 번에 최대 8개, 파일당 256 MiB까지 보냅니다. 폴더·심볼릭 링크·파일 약속(다른 앱이 나중에 생성하는 드래그 파일)은 지원하지 않습니다. 파일명과 내용 바이트를 그대로 유지하며 Finder 복사만으로는 자동 전송하지 않습니다. 로컬 파일 전체를 메모리나 임시 복사본에 올리지 않고 원본을 읽어 스트리밍합니다. 보내는 동안 원본을 편집하지 않는 편이 좋습니다.

전송이 끝나면 원격 경로들을 줄바꿈으로 구분해 복사합니다. 그 사이 다른 내용을 복사하거나 업무 상태가 바뀌면 클립보드를 유지합니다. 이때 **최근 파일**의 경로 복사 아이콘을 사용합니다. 기본 3개, **전체 N개**에서 최근 8개를 확인할 수 있습니다. `캡처 원본 유지`는 자동 캡처의 동작 설정이며 직접 선택한 파일 전송의 완료 경로 복사에는 적용하지 않습니다.

업무 OFF·잠금/절전·취소·연결 오류에서는 중단하고 자동 재전송하지 않습니다. 다시 드롭하거나 선택해서 보냅니다. 여러 파일 중 일부만 완료됐다면 완료된 항목은 최근 파일에서 경로를 복사할 수 있습니다. 파일 보관 용량은 이미지와 합산하며, 원격 일일 정리가 24시간 지난 파일과 오래된 전송 잔여물을 정리합니다. 로컬 원본은 삭제하지 않습니다.

앱 갱신 뒤 서비스가 보이지 않으면 Worklink를 종료 후 다시 열어 주세요. macOS **시스템 설정 → 키보드 → 키보드 단축키 → 서비스**에서 Worklink 항목을 활성화할 수도 있습니다. 이전 헬퍼를 사용하면 설정에서 원격 헬퍼를 다시 설치해야 합니다.

## 포트 상한에서 자동 교체

서버 16개·SSH 대상 8개 상한은 Worklink의 자원 관리 정책입니다. macOS 자체 제한은 아닙니다. 17번째 서버를 추가하면 현재 SSH 연결에서 최근 15초 안에 비활성으로 확인한 항목 중 가장 오래 비활성인 등록 하나를 제거합니다. 실행 중인 원격 서버 프로세스는 종료하지 않습니다. 제거한 포트는 등록 완료 안내에 표시합니다.

활성·미확인·연결이 끊긴 대상의 포트는 자동 제거하지 않습니다. 후보가 없으면 기존 등록을 유지하고 직접 제거하라는 안내를 표시합니다. SSH 대상 8개는 자동 제거하지 않습니다.

## N일 동안 사용하지 않은 포트 자동 정리

**설정 → 오래된 포트 정리**에서 켤 수 있습니다. 기본은 꺼짐·7일이며 3·7·14·30일 중 선택합니다. 정책 변경은 진행 중인 이미지·파일 전송과 SSH 연결을 재시작하지 않습니다.

업무 ON 상태에서 기존 서버 확인 결과를 이용해 24시간에 한 번 실행합니다. 마지막 활성 관측 이후 선택한 기간이 지났고 현재도 연결된 SSH에서 최근 15초 안에 비활성으로 확인한 포트만 정리합니다. 한 번도 활성화되지 않았다면 최초 관측부터 계산합니다. 과거에 기록하지 않았던 활동 시각은 추정하지 않고 새 관측부터 보수적으로 계산합니다. OFF·네트워크/SSH 단절 기간만으로 삭제하지 않으며 재연결 후 현재 상태를 확인해야 합니다. 실행 시점이 지연되어 확인이 오래됐다면 다음 확인 때로 보류합니다.

포트 상세의 핀 버튼 또는 설정의 **고정**을 누르면 일일 정리와 16개 상한 자동 교체에서 모두 보호합니다. 중지한 등록·활성·미확인 포트도 보호합니다. 정리는 해당 Worklink 포트 전달과 등록만 제거하고 원격 서버 프로세스나 다른 SSH·파일 전송을 종료하지 않습니다.

팝업 개발 서버 영역에 최근 정리 개수와 **되돌리기**가 나타납니다. 정리 목록은 마우스를 올려 확인할 수 있고 설정에는 최근 실행 시각을 표시합니다. 되돌리기는 최신 정리 묶음을 복원하고 다시 삭제되지 않도록 고정합니다. 복원 항목이 기존 포트와 충돌하거나 16개 상한을 넘거나 원래 SSH 대상이 없으면 전체 복원을 보류하고 기존 설정과 정리 기록을 유지합니다. 정리 기록은 앱 재시작 후에도 유지하며 다음에 다른 포트를 정리하거나 되돌릴 때 갱신됩니다.
