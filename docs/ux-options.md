# UX 선택 결과

현재 확정된 요구사항은 원본 이미지 품질 유지, 캡처 이벤트당 전송 작업 1개, 완료 시 원격 경로 복사, 하루 한 번 원격 이미지 정리, 수동 등록한 개발 서버 감시, 메뉴바 이름·주소·상태 표시와 기본 브라우저 열기입니다.

2026-10-05 사용자 선택: **1B, 2A, 3A, 4A, 5A, 6A**. 아래 결과를 현재 설계에 반영했습니다. 현재 구현했고 실제 AppKit 뷰를 렌더링해 시각 검증했습니다. 실제 화면 조작 도구의 오류와 미검증 범위는 validation.md에 기록합니다.

## 가장 먼저 해결할 작업 흐름

캡처 후 바로 에이전트에 붙여넣으면 전송이 아직 끝나지 않았을 수 있습니다. “전송 시작”, “원격 저장 완료”, “현재 클립보드에 그 파일 경로가 준비됨”을 구분해야 합니다. 완료 상태는 원격 ACK와 경로 복사까지 완료한 시점에 표시합니다. 전송 완료 전에 Cmd+V를 누르는 것을 앱이 가로채지는 않습니다.

전송 중 사용자가 다른 내용을 복사해 경로를 자동으로 넣지 못한 경우에는 “전송됨 · 경로 복사 필요” 상태와 재복사 동작을 제공합니다. 이전 이미지 경로가 아직 클립보드에 남아 있을 때도 새 이미지가 준비된 것처럼 표시하지 않습니다. 오류가 발생하면 해당 이미지의 재시도와 경로 복사가 필요한 상태를 분리합니다.

## 확정한 선택

| 번호 | 선택 | 동작 |
| --- | --- | --- |
| 1 | B | 메뉴바 상태만 표시. 시스템 배너·알림음은 기본으로 사용하지 않음 |
| 2 | A + 우클릭 토글 | 로그인 시 앱 자동 시작·업무 OFF. 좌클릭 목록, 우클릭 ON/OFF. OFF는 흐린 아이콘과 다른 모양 |
| 3 | A + 간단 주소 파서 | URL·호스트:포트·포트 숫자를 붙여넣고 이름·SSH 대상을 선택. 정규화 결과 미리보기 |
| 4 | A | 최근 5개 작업의 시각·대상·결과·경로 재복사. 썸네일은 초기 생략 |
| 5 | A | 서버 이름·접속 주소·상태를 기본 표시하고 원격 대상·상세 정보는 펼쳐보기 |
| 6 | A | 하루 한 번 24시간 지난 파일 정리 |

1번 상태 표시는 클립보드에 경로가 준비됐는지 구분합니다. 원격 업로드만 끝나고 클립보드를 갱신하지 못했다면 “경로 복사 필요”로 표시합니다. 오류는 메뉴바 오류 배지와 메뉴 안의 원인·해결 동작으로 보여줍니다. 반복 팝업이나 소리를 내지 않고 터미널의 포커스를 가져오지 않습니다.

2번 OFF 아이콘은 투명도를 낮추고 연결이 끊어진 형태로 바꿉니다. OFF여도 좌·우클릭을 받을 수 있는 버튼이며 비활성 버튼으로 처리하지 않습니다. ON/OFF는 tooltip과 메뉴의 상태 텍스트에도 표시합니다. 우클릭은 한 번의 누름/뗌 중 한 시점에서만 처리해 중복 토글을 막고, 메뉴 안에 명시적 ON/OFF 항목도 둡니다.

3번 입력은 **원격 개발 서버의 주소**입니다. 예를 들어 `http://localhost:4387/preview`를 붙여넣고 `office-mac`을 고르면 원격 포트·HTTP scheme·path를 채웁니다. 브라우저 열기용 로컬 URL은 실제로 배정된 로컬 포트로 별도 생성합니다. 이름은 직접 입력한 값을 우선하며 확인 가능한 HTML 제목은 보조 정보입니다. 중복 등록은 기존 항목을 보여주고 수정하도록 합니다. 입력 정규화는 [주소 파서 설계](address-parser.md)를 따릅니다.

4번 최근 작업은 원본 이미지 캐시를 계속 보관하는 기능이 아닙니다. 로컬에는 작은 작업 메타데이터만 유지하고 원격 ACK 후 임시 이미지 파일은 삭제합니다. 원격 정리로 사라진 파일은 경로를 다시 복사하는 대신 만료 상태를 보여줍니다. 경로 복사 전에 필요하면 해당 파일의 존재 여부를 원격에 확인합니다.

6번은 하루 한 번 실행해 24시간 지난 파일을 정리하는 것으로 확정했습니다. 일일 정리와 조합하면 실행 지연이 없을 때 실제 보관은 대략 24–48시간입니다. 보관 표시한 이미지는 제외하고, 로그아웃·전원 꺼짐으로 미실행한 정리는 다음 연결에서 보완합니다.

## 사용자 선택 없이 유지할 기본 동작

- 이미지는 원본으로 전송하며 크기 상한 때문에 전송할 수 없으면 알립니다. 자동으로 화질을 줄이지 않습니다.
- 업무 ON 동안 등록한 서버의 터널을 유지합니다. 서버 응답이 없어도 등록 정보는 남고 서버 재시작 시 다시 사용할 수 있습니다.
- 충돌한 로컬 포트의 기존 프로세스를 종료하지 않고 대체 포트를 사용자가 선택합니다.
- 서버 미등록·SSH 단절·원격 서버 대기·로컬 포트 충돌을 서로 다른 상태로 표시합니다.
- SSH 인증 오류나 용량 부족에는 원인과 해결 동작을 함께 보여줍니다. 일시적인 네트워크 실패는 기존 backoff 정책으로 복구합니다.
- 업무 OFF는 감시·전송·재연결을 멈추고, 이미지·서버 등록 기록 자체는 유지합니다.

## Worklink 자체 개발을 편하게 하는 방법

권장 순서는 **코어 CLI → 실제 두 Mac에서 전송·터널 확인 → 메뉴바 연결**입니다. 터미널에서 문제를 재현할 수 있도록 UI와 같은 기능을 CLI에서 실행할 수 있게 합니다. 사용자에게는 기본적으로 메뉴바 앱만 노출합니다.

개발 모드는 정식 앱과 앱 이름·저장 공간·SSH control socket·로컬 테스트 포트를 분리합니다. 테스트 inbox는 별도 임시 디렉터리를 쓰고 정리 시험이 실제 캡처를 지우지 않도록 합니다. 제품 LaunchAgent는 설치하지 않고 테스트용 정리 명령을 직접 실행합니다.

SSH 연결·클립보드 읽기·브라우저 열기·일일 정리 스케줄을 얇은 어댑터로 두어, 로컬에서 지연 ACK·전송 중 복사·단절·포트 충돌·파일 만료를 재현할 수 있게 합니다. 단순한 mock 결과만으로 실제 두 Mac 검증을 대체하지 않습니다.

초기에는 대시보드보다 `worklink doctor` 같은 진단 명령과 앱의 “진단 정보 복사”가 도움이 됩니다. 진단에는 현재 상태·앱 버전·실패 단계·소요 시간을 포함하고 이미지 내용과 인증 정보는 넣지 않습니다. CLI doctor는 구현했습니다. 앱 내 진단 정보 복사는 후속 편의 기능입니다.

## 확인한 참고 자료

기존 macOS 캡처 동작을 유지합니다. Control 키를 캡처 단축키에 추가하면 클립보드로 저장할 수 있습니다. 별도 캡처 UI는 초기에는 필요하지 않습니다. [Apple 스크린샷 안내](https://support.apple.com/en-us/102646)

메뉴바·알림의 플랫폼 가이드도 확인 대상으로 삼았습니다. 현재 웹 도구가 아래 HIG 페이지 본문을 추출하지 못했으므로, 위 추천안의 근거를 해당 페이지에서 확인한 규칙이라고 주장하지 않습니다. [Apple 메뉴바 HIG](https://developer.apple.com/design/human-interface-guidelines/the-menu-bar), [Apple 알림 HIG](https://developer.apple.com/design/human-interface-guidelines/notifications)
