# 클립보드 완료 동작 전환

영향 도메인: 로컬 AppKit 클립보드와 메뉴바, 원격 원본 다운로드. 사용자 결정: 자동 전송은 유지하고 상황별로 원본 유지 또는 완료 시 경로 복사를 선택.

## Step 1
- 원본 유지 모드는 자동 업로드 완료 시 클립보드 byte·type·changeCount를 유지.
- 경로 복사 모드는 기존 changeCount·업무 generation·대상 보호를 유지.
- 메뉴바 상단의 `캡처 원본 유지` 옵션을 ON/OFF할 수 있고 재실행에도 유지. 초기 기본은 기존 경로 복사 동작을 유지.
- 전환 자체는 클립보드 쓰기·재전송·업무/SSH 재시작을 하지 않음. 진행 중 전송은 완료 시 현재 설정을 적용.
- 명시적 최근 이미지 `경로 복사`는 원본 유지 모드에서도 작동.
- 최근 완료 이미지 `원본 복사`는 원격 원본을 요청 시 다운로드하고 hash 검증 후 같은 형식/byte로 기록. 자동 재업로드 금지, newer clipboard/업무 상태 보호, 임시 파일 즉시 제거.
- 테스트: 원본 보존·경로 모드·다른 내용 보호·지연 완료 전 모드 전환·선택 저장·수동 복사, 고정 팝업 회귀.
- [x] 실패 테스트 → 구현 → native 테스트/렌더 → 병렬 스펙·코드 리뷰 → 수정·재검증 → 로컬 커밋·설치 파일 업데이트.

## 실행 규칙

기존 stepped-plan-executor의 하네스 모드로 진행한다. 수용 기준은 위 사용자 결정과 spec S12/S15/S16이며 domain-contract의 원본 byte 보존·안전한 클립보드 쓰기를 유지한다. 설정은 사용자 전용 preferences에만 저장하며 repo에 개인 정보를 넣지 않는다. UI 테스트는 named pasteboard·별도 preferences를 사용한다. CUA 접근 거부를 우회하지 않는다. GitHub/PR/push는 수행하지 않는다.
