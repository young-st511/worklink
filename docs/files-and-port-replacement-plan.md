# 파일 전송과 비활성 포트 자동 교체

## 영향 도메인

Go core/storage/remote/transport, AppKit 입력·메뉴바. domain-contract의 원본 보존·ACK·OFF 중지·등록 대상만 감시를 따릅니다. 추가 상주 타이머는 없습니다.

## Step 1: 포트 교체

- [ ] S34 명세→실패 테스트→구현: 최대16개 포트에서 새 항목을 추가하면 정상 연결 중 확인된 비활성 포트의 비활성 기간을 기준으로 가장 오래된 항목 하나를 제거합니다. 인터넷/SSH 단절·미확인·활성 포트는 보호합니다. SSH 대상8개는 자동 제거하지 않습니다.
- [ ] 활동 기록은 변화 때만 영속화하고 재시작에서도 사용하되 실제 연결 확인 후에만 교체합니다. 제거 사실을 등록 결과로 알립니다.

## Step 2: 일반 파일 전송

- [ ] S35 명세→실패 테스트→구현: 메뉴바 드롭/Finder 서비스/파일 선택, 일반 파일 최대8개·각256MiB. 폴더·symlink·파일 약속은 제외합니다.
- [ ] 명시적 업무ON/연결된 이미지 전송 SSH 대상으로 전송, 전용 채널에서 원본 스트리밍/SHA/ACK, 진행률·취소·최근 파일/경로 복사, 완료 batch 경로 자동복사는 기존 clipboard generation/changeCount guard를 따릅니다.
- [ ] 파일명은 전송ID별 폴더에서 유지하고 기록 기반24시간 일일정리에 포함합니다. 전송 실패/OFF에서는 자동 재전송하지 않고 다시 보내게 합니다. 사용자 원본은 삭제하지 않습니다.
- [ ] 기존 캡처/터널 회귀·Go race/vet·native fixture·실제 SSH 임시파일·light/dark 렌더

## 실행 규칙

stepped-plan-executor 하네스의 명세→실패 테스트→구현→검증→두 병렬 스펙/코드 리뷰→수정·재검증→문서·커밋·push를 따릅니다. 구현은 주 에이전트가 수행하고 리뷰만 위임합니다. 사용자 실제 클립보드·이미지는 테스트에 사용하지 않습니다. CUA 거부를 우회하지 않고 실제 제품 마우스 검증과 native fixture 검증을 구분합니다. 설치본/필요한 원격 헬퍼를 갱신하되 제품 앱 자동 재시작은 하지 않습니다.
