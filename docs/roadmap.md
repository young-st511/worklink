# 개발 순서

현재 요청에 따른 결과물은 타당성 검토 문서와 비용 측정 실험입니다. 아래는 후속 제품 개발 제안이며 이번에 구현된 기능 목록이 아닙니다.

## 1. 전송과 연결 코어

- Go CLI와 원격 stdio 헬퍼, 버전 협상·길이 제한·취소 구현.
- 기존 SSH 별칭 재사용, 전용 master 생성·종료, 포트 add/remove/list.
- 파일 1개 명시적 전송, 원격 저장 완료 ACK, image latest/list.
- 원본 바이트·형식 유지, 추가 압축·리사이즈·자동 재인코딩 없음.
- 파일명에 Worklink 접두어·UTC 시각·UUID, 완료 후 로컬 임시 파일 삭제.
- 전송 중 단절·재시도 중복·동시 호스트 전환·파일명/경로 입력 검증.
- 실제 두 Mac에서 등록된 포트와 이미지 파일 전달 확인.

완료 기준: 기존 터널링·이미지 전송 스크립트의 핵심 기능을 수동 CLI로 대체할 수 있어야 합니다. 기존 시스템 설정은 변경하지 않습니다.

## 2. 업무 중 자동화

- Swift 메뉴바·로그인 자동 시작/업무 OFF·좌클릭 목록/우클릭 토글·OFF 아이콘 흐리게 및 모양 변경·무음 상태 표시·최근 전송 5개·완료 시 원격 경로 클립보드 복사.
- 이미지 전송 opt-in, 변경 번호 확인, 접근 거부·잠금·절전 처리.
- 캡처 이벤트당 작업 1개·전송 직렬화·크기/큐 제한·재시도 중복 방지·업로드 중 클립보드 변경 보호.
- SSH 대상·원격 loopback 주소·포트·로컬 포트를 수동 등록하고 등록 항목만 감시, 연결 단절 후 터널 복구.
- 간단 주소 파서와 등록 미리보기, 메뉴바 서버 이름·로컬 접속 URL·상태 표시 및 원격 대상 펼쳐보기, 항목 클릭 시 기본 브라우저 열기, 등록명 우선·선택적 HTML 제목 확인과 캐시.
- 원격 일일 cleanup 작업·최소 24시간 보관·미실행 시 다음 연결에서 보완, 파일명·관리 기록으로 삭제 범위 제한.
- 로컬 및 원격 프로세스 트리 CPU/RSS와 시스템 에너지 A/B 측정.

완료 기준: 30분 유휴, 4K 캡처 100회, 네트워크 단절, 절전 복귀 시험에서 자원 목표와 상태 복구가 확인되어야 합니다. 에이전트에서 실제 파일을 읽는 수동 확인도 포함합니다.

## 3. 필요성이 확인된 기능

- 선택적 스크린샷 폴더 모드와 프로젝트별 전송 목적지.
- 자동 시작·패키징·서명·권한 안내·배포 라이선스 결정.
- Go 메모리가 목표를 넘으면 Swift 통합 또는 Rust 코어 비교.
- localhost 유지가 필요 없는 사용자용 Tailscale Serve 모드 검토.

전체 리스너 자동 발견·개발 서버 실행 wrapper는 현재 범위에서 제외했습니다. 전체 화면 스트리밍, 양방향 텍스트 클립보드, 전체 파일 동기화, 에이전트 프롬프트 자동 실행도 초기 범위에 포함하지 않습니다.
