# Worklink

집의 Mac과 사무실의 Mac 사이에서 개발 서버 연결과 스크린샷 전달을 묶는 작은 업무 도구입니다.

Tailscale + SSH + Zellij + 터미널 코딩 에이전트를 사용하는 환경을 대상으로 합니다. 업무 모드를 켜두면 이미지 전달과 등록된 포트 연결을 관리하고, 업무를 마치면 감지와 연결을 멈추는 macOS 메뉴바 앱입니다.

**현재 상태: Go 코어 + AppKit 메뉴바 앱 구현, 실제 SSH·원본 전송·네이티브 클립보드 경로 복사와 AppKit 뷰 렌더 검증.**

아이콘은 연결 모티프의 native Liquid Glass 레이어를 사용하며 [아이콘 원본과 제작 안내](assets/README.md)를 포함합니다.

빌드는 `make app`, 설치·사용 방법은 [시작 안내](docs/getting-started.md), 검증 결과와 한계는 [검증 기록](docs/validation.md)을 참고해 주세요.

## 검토 결론

구현 가능성이 높습니다. 비용을 좌우하는 것은 언어보다 **확인 주기, 프로세스 생성 횟수, 이미지 크기, 재연결 방식**입니다.

- 로컬은 Swift/AppKit 메뉴바 앱, 통신·전송 코어는 Go입니다.
- 기존 Tailscale과 시스템 OpenSSH를 재사용하고, 대상 Mac마다 Worklink 전용 SSH 연결 하나에서 제어·전송·포트 전달을 처리합니다.
- 클립보드 변경 번호를 1초 간격으로 확인하고, 바뀐 경우에만 이미지 처리 단계로 넘어갑니다.
- 이미지는 추가 압축·리사이즈·자동 재인코딩 없이 원본을 전송하며, 캡처 이벤트마다 전송 작업 1개를 생성합니다.
- 전송 완료 시 원격 경로 자동 복사 또는 로컬 원본 유지 모드를 선택합니다. 최근 이미지에서 경로·원본을 수동 복사할 수도 있습니다. 그 사이 다른 내용을 복사했다면 덮어쓰지 않습니다.
- 개발 서버는 SSH 대상·원격 loopback 주소·포트를 수동 등록하고 등록된 항목만 감시합니다. 전체 리스너 자동 발견은 현재 범위에서 제외합니다.
- 메뉴바에서 서버 이름·로컬 접속 URL·원격 대상·상태를 확인하고, 클릭하면 로컬 터널 URL을 기본 브라우저에서 엽니다. 이름은 등록명을 우선하고 가능하면 페이지 제목을 보조 정보로 사용합니다.
- 원격 이미지는 `worklink-capture-<UTC 시각>-<UUID>.<원본 확장자>` 이름으로 저장하고 하루 한 번 오래된 파일을 정리합니다.

전체 앱의 저전력 동작은 아직 검증하지 않았습니다. [타당성 검토](docs/feasibility.md), [동작 설계](docs/design.md), [개발 순서](docs/roadmap.md)에 판단과 남은 실험을 기록했습니다.

사용자가 확정한 [UX 선택 결과](docs/ux-options.md)는 무음 상태 표시, 로그인 시 앱 자동 시작·업무 OFF, 우클릭 ON/OFF, 간단 주소 입력, 최근 이미지 5개, 상세 정보 펼쳐보기, 하루 한 번 24시간 지난 이미지 정리입니다. [주소 파서 설계](docs/address-parser.md)에 입력 정규화 규칙을 기록했습니다.

## 비용 측정 실험

macOS와 Xcode Command Line Tools가 필요합니다. 외부 패키지는 없습니다.

```sh
make probe
.build/clipboard-cost timer-only 30 1
.build/clipboard-cost clipboard 30 1
```

실험은 지정한 시간 후 종료합니다. 클립보드 변경 번호만 읽으며 이미지·텍스트 내용을 읽거나 덮어쓰지 않습니다. SSH 연결, 네트워크 전송, 상주 서비스 설치도 수행하지 않습니다.

Python 3가 있다면 `python3 experiments/listener-cost.py`로 현재 사용자 소유 TCP 리스너 검색 비용을 30초 동안 측정할 수 있습니다. 소켓·프로세스 목록은 저장하지 않습니다. 이는 초기 비교 실험이며 현재의 등록제 설계에서 전체 리스너 검색은 사용하지 않습니다.

JSON 출력의 CPU 비율은 한 코어를 100%로 보는 **실험 프로세스만의 실행 중 평균**입니다. 메모리는 초기화를 포함한 최대 RSS입니다. 타이머 콜백 수는 시스템의 실제 wakeup 수가 아닙니다. 측정 방법과 한계는 [실험 기록](docs/measurements.md)을 확인해 주세요.
